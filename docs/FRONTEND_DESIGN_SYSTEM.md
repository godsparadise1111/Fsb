# سیستم طراحی و پوسته رابط کاربری F-S

## دامنه

این سند قرارداد رابط کاربری مشترک برنامه وب F-S را ثبت می‌کند. هدف، جلوگیری از ایجاد رنگ‌بندی، تایپوگرافی و الگوهای تعاملی متفاوت در هر ماژول است.

## Theme Mode

کنترل پوسته در تمام صفحات از طریق کامپوننت مشترک `apps/web/src/components/theme-control.tsx` در دسترس است.

حالت‌ها:
- `light`: پوسته روشن
- `dark`: پوسته تیره
- `system`: پیروی از تنظیمات سیستم‌عامل و تغییر زنده هنگام تغییر تنظیم سیستم

انتخاب کاربر در مرورگر با کلید `fsb.theme.mode` ذخیره می‌شود. مقدارهای معتبر فقط `light`، `dark` و `system` هستند. مقدار نامعتبر یا نبود مقدار به `system` برمی‌گردد.

کامپوننت، ویژگی‌های `data-theme` و `data-theme-mode` را روی عنصر ریشه تنظیم می‌کند. همه اجزای جدید باید از توکن‌های CSS استفاده کنند و نباید رنگ ثابت مختص یک پوسته تعریف کنند.

## توکن‌های طراحی

توکن‌ها در ابتدای `apps/web/src/app/globals.css` تعریف شده‌اند:

| گروه | توکن‌ها |
|---|---|
| سطوح | `--fsb-bg`, `--fsb-surface`, `--fsb-surface-muted`, `--fsb-surface-raised` |
| متن | `--fsb-text`, `--fsb-text-muted`, `--fsb-text-soft` |
| مرزها | `--fsb-border`, `--fsb-border-strong` |
| رنگ برند | `--fsb-primary`, `--fsb-primary-hover`, `--fsb-primary-soft`, `--fsb-accent` |
| وضعیت | `--fsb-success`, `--fsb-warning`, `--fsb-danger` و پس‌زمینه‌های متناظر |
| جلوه‌ها | `--fsb-shadow`, `--fsb-shadow-strong`, `--fsb-radius` |

برای مثال:
```css
.new-panel {
  color: var(--fsb-text);
  background: var(--fsb-surface);
  border: 1px solid var(--fsb-border);
  border-radius: var(--fsb-radius);
  box-shadow: var(--fsb-shadow);
}
```

## تایپوگرافی فارسی

فونت متغیر Vazirmatn از بسته محلی `@fontsource-variable/vazirmatn` بارگذاری می‌شود؛ بنابراین برای نمایش متن فارسی به سرویس فونت خارجی وابسته نیست. فونت در Root Layout ثبت شده و از طریق `--fsb-font` به همه صفحات می‌رسد.

وزن‌های موردنیاز با فونت متغیر قابل استفاده‌اند. برای اعداد و محتوای لاتین، fallbackهای استاندارد در همان stack حفظ شده‌اند.

## اصول UI/UX

- اجزای جدید باید از رنگ‌ها و سطوح توکنی استفاده کنند.
- وضعیت‌ها فقط با رنگ منتقل نشوند؛ متن یا نشانه متنی نیز لازم است.
- دکمه‌ها، ورودی‌ها و لینک‌ها باید focus قابل مشاهده داشته باشند.
- انیمیشن‌ها کوتاه و محدود باشند و `prefers-reduced-motion` رعایت شود.
- متن‌های فارسی راست‌چین باشند؛ کد، شناسه‌ها، ایمیل و داده‌های ذاتاً LTR باید با جهت مستقل نمایش داده شوند.
- برای عملیات اصلی، دکمه و برچسب واضح استفاده شود و آیکون به‌تنهایی جایگزین نام عملیات نشود.
- جداول عریض باید داخل ظرف پیمایش کنترل‌شده باشند؛ در صفحات کوچک نباید کل صفحه را به اسکرول افقی مجبور کنند.
- پنل‌ها و فرم‌ها باید در عرض کم به تک‌ستونه تبدیل شوند و عرض محتوا از viewport بیرون نزند.

## قواعد چیدمان واکنش‌گرا

نقاط شکست پایه فعلی:
- تا 1100px: کاهش فاصله‌های افقی و padding.
- تا 800px: چیدمان منعطف‌تر، دو ستونه شدن شبکه ماژول‌ها و آماده‌سازی پنل‌ها برای تبلت.
- تا 600px: محتوای تک‌ستونه، کنترل‌های تمام‌عرض در بخش‌های پرتراکم و فضای امن پایین صفحه برای کنترل پوسته.

این قواعد، پایه مشترک هستند؛ هر ماژول پیچیده مانند طراح فرایند یا فرم‌ساز باید آزمون اختصاصی در اندازه‌های موبایل و تبلت داشته باشد.

## کنترل کیفیت

این تغییرات در این مرحله روی کد اعمال شده‌اند، اما build، lint، آزمون مرورگر و ارزیابی بصری اجرا نشده‌اند. پس از نصب وابستگی جدید و آماده‌شدن محیط Staging باید:
1. `npm install` در ریشه workspace اجرا شود.
2. build و lint برنامه وب اجرا شوند.
3. پوسته روشن، تیره و سیستم در تمام مسیرهای احراز هویت‌شده و عمومی بررسی شود.
4. فونت فارسی در شبکه قطع از اینترنت نیز بررسی شود.
5. صفحات اصلی، فرم‌ساز، فرایندساز، کارتابل، گزارش‌ها و مدیریت سازمان در عرض‌های 360، 390، 768، 1024 و 1440 پیکسل بازبینی شوند.
