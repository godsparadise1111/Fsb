# F-S | سامانه مدیریت فرایندهای سازمانی (BPMS)

سامانه F-S برای طراحی، اجرا و پایش فرایندهای سازمانی، گردش کارها، فرم‌های پویا و ساختارهای چندسطحی سازمان توسعه داده می‌شود.

> وضعیت: هسته بک‌اند (هویت، چندمشتری، سازمان، فرم، فرایند، موتور گردش‌کار، گزارش‌ساز، اعلان‌ها) و زیرساخت استقرار با Docker پیاده‌سازی شده و در مرحله تثبیت و پذیرش روی Staging است. جزئیات هر فاز در [وضعیت پروژه](docs/PROJECT_STATUS.md) و [نقشه راه](docs/ROADMAP.md) آمده است.

## جهت‌گیری تجاری
F-S با رویکرد محصول BPMS سازمانی و قابلیت عرضه به‌صورت خودمیزبان و در آینده SaaS طراحی می‌شود. اصول بازار هدف، بسته‌بندی نسخه‌ها، الزامات چندمشتری و معیارهای پذیرش در [راهبرد محصول و تجاری](docs/PRODUCT_STRATEGY.md) آمده است.

## فناوری‌ها و معماری
- Frontend: Next.js 14
- Backend: NestJS
- ORM: TypeORM
- Database: PostgreSQL (مهاجرت‌های SQL با ledger و checksum)
- Deployment: Docker / Docker Compose
- Server OS: Ubuntu Server 24.04 LTS
- Architecture: Modular Monolith

## اهداف اصلی
- ساختار سازمانی چندسطحی با واحدها و زیرواحدهای تو در تو
- کاربران، نقش‌ها، مجوزها، سمت‌ها و انتساب کاربران به سمت
- فرم‌های پویا و نسخه‌بندی فرم
- تعریف و نسخه‌بندی فرایندها
- موتور اجرای گردش کار و کارتابل وظایف
- تخصیص وظیفه به یک یا چند نفر
- تاریخچه اقدامات، ممیزی، اعلان‌ها و گزارش‌ها

## قاعده کلیدی: تخصیص چندنفره
در سیاست `ALL_ASSIGNEES`، وظیفه فقط زمانی تکمیل می‌شود که تمام کاربران الزامی اقدام معتبر خود را ثبت کرده باشند. اقدام هر کاربر جداگانه ذخیره می‌شود و وضعیت کلی وظیفه در Backend محاسبه می‌شود. سیاست `ANY_ASSIGNEE` برای سناریوهایی است که اقدام اولین فرد کافی است.

## ماژول‌ها
1. Identity & Access — هویت، نقش و مجوز
2. Organization — سازمان، واحدها، زیرواحدها، سمت‌ها و عضویت‌ها
3. Forms — فرم‌ساز، فیلدها، اعتبارسنجی و پاسخ‌ها
4. Process Definition — تعریف و نسخه‌بندی فرایند
5. Workflow Runtime — نمونه فرایند، مراحل و انتقال‌ها
6. Tasks & Assignment — وظایف و تخصیص‌های چندنفره
7. Audit & History — تاریخچه و رویدادهای ممیزی
8. Notifications — اعلان‌ها
9. Reporting — داشبورد و گزارش‌ها

## اصول توسعه
- منطق دامنه و گردش کار در Backend مرجع نهایی است.
- نسخه منتشرشده فرم و فرایند درجا ویرایش نمی‌شود.
- اقدام هر کاربر و تغییر وضعیت باید قابل ممیزی باشد.
- عملیات حساس باید تراکنشی و در برابر درخواست تکراری و رقابت هم‌زمان مقاوم باشد.
- اسرار و فایل‌های محیطی واقعی نباید وارد Git شوند.
